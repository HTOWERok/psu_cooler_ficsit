# Как вести этот проект в репозитории

Практическая памятка: что куда класть, как публиковать, чем отличаются площадки.

---

## 1. Структура репозитория

```
psu_cooler_ficsit/
├─ README.md              ← главная страница (RU), её читают первой
├─ LICENSE                ← CC BY-NC-SA 4.0
├─ .gitignore             ← отсекает _wip, кэш Python, gcode и служебные .3mf
├─ stl/                   ← только печатные файлы + отчёты
│  ├─ 01_base.stl
│  ├─ 02_wall_front.stl
│  ├─ 03_wall_rear.stl
│  ├─ 04_roof.stl
│  ├─ 05_filter_tray.stl
│  ├─ manifest.json       ← объёмы, габариты, ориентации
│  └─ print_check.json    ← аудит печати
├─ renders/               ← превью: 01_hero, 02_open, 03_exploded, 04_front, 05_detail, 06_top
├─ src/                   ← параметрический исходник (Python) + requirements.txt
├─ print/                 ← пресеты ABS, проекты Bambu Studio (.3mf), скрипты сборки
└─ docs/
   ├─ THINGIVERSE.md      ← текст публикации (EN)
   ├─ CHANGELOG.md        ← по строке на версию
   └─ REPO.md             ← этот файл
```

Живой пример: <https://github.com/HTOWERok/psu_cooler_ficsit> — тег `v1.0`, ветка `main`.

Правила, которые экономят нервы:

- **`stl/` — только актуальные файлы.** Версии не хранить как `base_v2_final.stl`; для этого есть git.
- **Превью — PNG, не скриншоты экрана.** 1600 px по длинной стороне достаточно.
- **Исходник обязателен.** Люди охотнее печатают и благодарят, если могут поправить размер под свой БП.
- **`manifest.json` рядом с STL** — сразу видно, какой файл как печатать.

---

## 2. Нейминг файлов

`NN_название.stl`, где `NN` — порядковый номер сборки (01, 02…). Тогда в слайсере детали стоят в правильном порядке и не путаются:

| № | Деталь |
|---|---|
| 01 | цоколь (база) |
| 02 | передняя стенка |
| 03 | задняя стенка |
| 04 | крышка |
| 05 | фильтр-лоток |

Имя файла = имя детали в README и в BOM. Не переименовывать после публикации: ссылки в описаниях ломаются.

---

## 3. Куда публиковать

| Площадка | Что загружать | Особенности |
|---|---|---|
| **Printables** | STL + превью + текст из `docs/THINGIVERSE.md` | лучший поиск, есть «parametrized», поддерживает .3mf; самый удобный редактор описания |
| **Thingiverse** | STL + превью | огромная аудитория, но редактор слабый — вставлять текст абзацами |
| **MakerWorld** | STL/3MF + превью | любит 3MF с раскраской по деталям и рейтинг за печать; хорошо для «печатай в один клик» |
| **GitHub** | всё, включая `src/` | основная точка правды; в README — картинки из `renders/` |

Порядок: GitHub → Printables (основная ссылка) → Thingiverse/MakerWorld (копия с обратной ссылкой на GitHub).

## 4. Теги и заголовок

Заголовок: **FICSIT-Style Cooling Tower for 165 × 82 × 35 mm Laptop Power Brick (2 × 80 mm fans)** — в нём есть и стиль, и функция, и ключевые размеры. Люди ищут именно «power brick», «psu cooling», «80mm fan mount».

Теги: `power supply`, `psu`, `cooling`, `fan`, `80mm`, `laptop`, `desk`, `organizer`, `functional`, `no supports`, `parametric`, `satisfactory`. Не злоупотреблять брендовыми — одно упоминание стиля достаточно.

---

## 5. Лицензия

- **Модель:** CC BY-NC-SA 4.0. Печать, правка, публикация — с указанием автора и той же лицензией, без продажи.
- **Стиль FICSIT:** товарный знак Coffee Stain Studios. В описании обязательно оговорка «fan art, not affiliated». Если планируется продажа печати — убрать надписи и публиковать как «Industrial Cooling Tower».
- Файл `LICENSE` кладётся в корень; в README — короткий блок «License».

---

## 6. Версии

Схема простая, без семантики: тег `v1.0`, `v1.1`… В `CHANGELOG.md` — одна строка на версию:

```
## v1.0
- Первый релиз: цоколь, 2 стенки, крышка, фильтр-лоток.
```

Любое изменение геометрии → новая версия и пересборка `stl/` + `manifest.json`.

## 8. Мелочи, которые заметят

- Указать **ориентацию печати для каждой детали** — половина вопросов в комментариях снимается.
- Указать **точные длины винтов** — вторая половина.
- Честно написать, что модель проверена на нависания (у нас 0 поддержек, `print_check.py`).
- Добавить строку «ремонтопригодность»: все узлы на винтах, фильтр снимается без инструмента.

## 9. Работа с репозиторием

Репозиторий: <https://github.com/HTOWERok/psu_cooler_ficsit> (ветка `main`, тег `v1.0`).

Обычный цикл правки:

```powershell
cd C:\Users\Craftroom\Desktop\DeepSeek\psu_cooler_ficsit
python src\export_stl.py          # или просто поправили README
git status                        # что изменилось
git add -A
git commit -m "v1.1: подгонка под БП 170×85×40"
git push
```

Git for Windows (портативный) лежит в `%LOCALAPPDATA%\Programs\PortableGit`, `git` уже в PATH.
Учётные данные сохранены в `%USERPROFILE%\.git-credentials` — когда срок токена истечёт,
`git push` один раз спросит новый (в поле пароля — токен, не пароль от аккаунта).

Релиз новой версии: `git tag -a v1.1 -m "..." && git push origin v1.1`, затем на GitHub
Releases → Draft a new release → выбрать тег → приложить STL.

Служебные каталоги (`print/_wip/`, `print/_gcode/`, `__pycache__`, `print/_slice_*.3mf`)
в репозиторий не попадают — они в `.gitignore`.
